# .brain/modes/adoption.md - BROWNFIELD ADOPTION PROTOCOL

*MODE CONTRACT: living document; Gate 6 may refine it under double veto, but the legacy boundary rule and the adapt-don't-reeducate principle may never be weakened.*

## ENTRY CRITERIA
Activated when the brain finds itself newly installed in a PRE-BUILT codebase: substantial product source exists while the brain's memory is empty (no ledger entries, zero scoreboard runs, no plan artifacts), and/or git history predates the brain's files. Detection is a Gate 0 duty (root bootloader Section 9); the operator may also invoke it directly ("adopt this project"). Runs ONCE per project — completion is recorded by the Provenance stamp and the Adoption Report.

## THE PRIME LAW
The brain adapts to the house; the house is not refactored to match the brain. Loaded skills inform NEW work — they are never grounds to rewrite working pre-brain code. The brain claims neither credit nor blame for what predates it; it is responsible only for what changes on its watch.

## MANDATORY SEQUENCE
1. **Stamp provenance:** set `Project Provenance: BROWNFIELD (adopted YYYY-MM-DD)` in bootloader Section 1, alongside the environment-matrix fill.
2. **Archaeology pass:** map the existing architecture (layers, modules, entry points), the reigning conventions (naming, state management, error handling), and the dependency reality (versions, licenses where visible) into the ledger's Codebase and Architectural Constraints section — so every future session starts oriented and skills adapt to the house style.
3. **Coverage honesty audit:** record the true state of the test suite — what exists, what it covers, what it does not — so Gate 2's "full suite passes" is correctly calibrated: a passing empty suite proves nothing, and every future plan must account for the real net beneath it.
4. **Declare the legacy boundary:** pre-brain code is marked territory — full Gate 3 regression sweeps whenever touched, drive-by refactors forbidden, improvements to legacy areas only as explicitly planned tasks.
5. **Baseline recommendations:** recommend — never force — the two baseline sweeps (`release_sweep` for accumulated security state; `deep_qa` for the current defect landscape) and a Build Tier declaration for the project. Record the operator's decisions.

## EXIT ARTIFACT
The Adoption Report: architecture map, convention summary, coverage truth, the legacy boundary declaration, and the baseline recommendations with the operator's decisions. Once delivered, ordinary pipeline work begins.
