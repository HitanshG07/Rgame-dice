MY FIRST FIX FOR CLASS A WAS WRONG, and the panel said so. Annotating the local
(`local out: Distribution = table.create(#mass)`) does not cure the mismatch, it
only makes it explicit. The COLUMN NUMBERS were the tell: the warning moved to
(75, 28), which points at `table.create` itself, not at the variable.

Recorded because it is the useful lesson from this run: read the column, not
just the line. Five warnings cleared out of the ~40 expected, and the shortfall
is what exposed the wrong diagnosis.

Correct fix: supply a fill value — `table.create(n, 0)` for number arrays,
`table.create(n, "")` for the string array — and plain `{}` where the elements
are TABLES, because a fill value there would share ONE table across every face.
That would have been a real bug traded for a clean panel.
